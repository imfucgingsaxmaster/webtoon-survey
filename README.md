# Webtoon Radar

네이버웹툰 **공개 정식 작품 카탈로그 전체**를 매주 조사하는 Python · Streamlit · SQLite 프로젝트입니다. 요일별 연재작, 매일+, 완결 목록을 모두 순회하고 작품 ID로 중복을 제거합니다. 특정 인기작 표본이나 첨부 조사 PDF의 작품 목록으로 대상을 제한하지 않습니다.

## 결과물과 실행

```sh
pip install -r requirements.txt
python -m unittest tests -v
python radar.py
python metadata.py
python radar.py --offline
streamlit run app.py
```

저장된 관측만 분석할 때는 `python radar.py --offline`을 실행합니다. 대시보드는 네트워크 수집 없이 저장된 실제 관측을 읽습니다.

- 웹 대시보드: 작품명·작가·태그 검색, 장르, 관심·다운로드·댓글 태그 조합(모두/하나 이상), 최소값 필터, 지표 정렬, 상태·목록 필터, Excel 다운로드
- Excel: 전체 작품, 목록별 인기순 위치, 범위 검증 및 출처. 별도 `webtoon_radar_search.xlsx`에 장르·공개 지표·원문 표시값·태그·작품별 관측 시각을 보존합니다.
- 요약 PDF: 작품 수·상태·수집 범위와 제한사항
- SQLite: 관측 시점별 작품 및 목록 소속, JSON: 재현 가능한 원자료 메타데이터
- 주간 비교: 이전 관측 대비 목록 진입·이탈, 같은 목록 내 위치 변화. 첫 실행에서는 추세를 만들지 않습니다.

## 수집 범위와 자료 원칙

출처는 [네이버웹툰 공개 목록](https://comic.naver.com/webtoon)과 작품 페이지입니다. 공개 웹사이트가 제공하는 JSON 목록·작품 정보를 이용하며 공식 계약형 API라고 주장하지 않습니다. 작품 ID, 제목, 작가, 공개 별점, 연재 상태, 목록 내부 위치, 공개 관심 수, 장르·공식 태그를 보관합니다. 정식 공개 목록 밖의 베스트도전·도전, 비공개·판매 종료·앱 전용 작품까지 포함한다는 의미는 아닙니다.

수집 전 [robots.txt](https://comic.naver.com/robots.txt)를 다시 확인하고 허용된 목록·작품 정보 경로만 1.2초 간격으로 요청합니다. 본문·이미지·댓글 내용·개인정보를 수집하지 않으며 로그인·쿠키·보호장치 우회를 사용하지 않습니다. 차단·속도 제한·응답 구조 변경은 재시도하지 않고 해당 수집을 중단하며 기존 관측을 유지합니다. 로그인·연령 확인 등 다른 경로로 이동하는 작품은 이동을 진행하지 않고 제외 기록을 남깁니다. robots 허용은 별도 이용허락이나 무제한 재사용 허가를 뜻하지 않습니다. [이용약관](https://member.webtoon.naver.com/policy/terms)을 따르는 비상업 과제용 메타데이터 조사이며 정책 변경 시 수집을 중단하고 재검토해야 합니다.

완결 목록은 응답의 총 작품 수와 모든 페이지 수를 대조합니다. 요일별·매일+는 응답 배열 전체를 읽습니다. 수집 중 목록 변동이 발견되면 결과를 게시하지 않습니다. 여러 요청의 결과이므로 수집 시작·종료 시각 사이의 관측입니다.

공개 별점은 이용자 평가이며 조회수·매출·이용자 수가 아닙니다. 인기순 위치는 해당 목록 내부 정렬 순서입니다. 요일 간 위치를 합산한 통합 순위나 공개되지 않은 지표를 생성하지 않습니다. 목록 진입·이탈을 곧바로 신작·서비스 종료로 해석하지 않습니다.

## 네이버시리즈

[시리즈 robots.txt](https://series.naver.com/robots.txt)는 만화 전체 분류와 검색 경로의 자동 접근을 제한합니다. 허용된 [만화 홈](https://series.naver.com/comic/home.series)·[일간 TOP100](https://series.naver.com/comic/top100List.series)에서 발견한 작품과 이전에 발견한 작품의 공개 상세 페이지만 확인합니다. **시리즈 전체 카탈로그가 아닙니다.** 장르 링크의 표시명은 읽지만 제한된 분류 링크를 따라가지 않습니다.

## 관심 수와 태그 검색

- **관심 수는 네이버웹툰 작품 페이지**의 공개 집계 `favoriteCount`입니다. 개인의 관심 등록 상태 `favorite`는 저장하지 않습니다.
- 시리즈 다운로드·댓글 수는 공개 작품 페이지의 표시값입니다. `9,985만`, `2억 8,683만`, `1.4만`은 숫자로 환산하되 원문과 근삿값 표시를 함께 보관합니다. 댓글 본문은 읽지 않습니다.
- 장르는 공개 표기 그대로 사용합니다. 웹툰의 공식 태그도 보존하며 제목으로 장르를 추정하지 않습니다.
- `관심:10만 이상`, `다운로드:100만 이상`, `댓글:1만 이상` 등의 누적 기준 태그를 만듭니다. 태그의 모두/하나 이상 포함 조건, 장르, 최소값, 검색어를 함께 적용할 수 있습니다. 축약 표시값의 경계는 실제 정확한 값과 다를 수 있습니다.
- 미제공·미수집은 빈 숫자 값으로 유지하며 0으로 바꾸지 않습니다. 서로 다른 플랫폼의 지표를 이름으로 결합하지 않습니다. 식별자는 `(플랫폼, 작품 ID)`입니다.
- 목록과 상세정보는 관측 시각이 다릅니다. 대시보드는 전체 웹툰 목록을 항상 유지하고 상세 확인 수·작품별 관측 시각을 표시합니다. 과거 목록 비교와 최신 상세 지표는 구분합니다.

`python metadata.py`는 **모든 웹툰 목록 작품**을 대상으로 상세정보를 확인합니다. 4천여 작품은 요청 간격 때문에 첫 실행에 약 85분 이상 걸릴 수 있습니다. 이후 144시간 이내 관측은 재사용합니다. 20건마다 체크포인트를 저장해 중단 후 이어서 진행할 수 있습니다. `--webtoon-limit 100 --series-limit 100`으로 한 번의 요청 수를 제한할 수 있고 `0`은 해당 플랫폼을 건너뜁니다. 제한 옵션은 기본 전수 대상 목록을 축소하지 않습니다.

## 주간 자동 실행

GitHub Actions `Weekly Webtoon Radar`: 매주 월요일 **09:17 한국시간** 및 수동 실행. 테스트 → 전체 공개 목록 → 관심·장르·시리즈 지표 → SQLite/Excel/PDF → 관측 이력 저장 순서입니다. 코드 변경 시에는 플랫폼별 최대 100건으로 실제 연결을 검증하고, 예약·수동 실행은 요청 수 제한 없이 전체 대상을 갱신합니다. 실행 상한은 150분입니다. `catalog_latest.json`, `metadata_latest.json`, `history/`, `metadata_history/`를 봇이 갱신합니다. 상세 수집 중 일부가 실패해도 성공한 관측을 보존하고 실패 상태를 표시합니다. 산출물은 Actions 실행 화면의 Artifacts에서 내려받습니다(90일 보존). 저장된 관측 이력으로 다음 실행의 SQLite를 재구축합니다. GitHub 예약 작업은 지연되거나 비활성 저장소에서 중단될 수 있습니다.
