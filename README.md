# Webtoon Radar

네이버웹툰과 네이버시리즈의 작품을 연결해 표지 검색, 작품별 지표 변화, 제작사별 순위를 제공하는 Python · Streamlit · SQLite 프로젝트입니다.

[공개 대시보드](https://webtoon-survey-muhdfbebtwejruqvugroi6.streamlit.app/) · [자동 실행 기록](https://github.com/imfucgingsaxmaster/webtoon-survey/actions)

## 검색과 제작사별 보기

- **연재·휴재 / 완결 보관함 / 제작사별** 화면을 구분합니다. 작품 카드에서 상세 지표와 실제 관측 그래프를 열 수 있습니다.
- 작품명·작가·태그·장르·연재처·연재요일·신작·관심·다운로드·댓글 조건을 조합합니다. 신작은 공식 목록의 `new == true`만 사용하며 회차 UP 표시와 구분합니다.
- 상세 화면에서 **연재요일**과 **제작사**를 확인합니다. 요일은 공식 작품 정보가 우선이며 없으면 목록 소속을 사용합니다. 완결 작품은 마지막 편성을 표시합니다.
- **제작사**는 네이버시리즈 작품 페이지의 **출판사** 표기 기준입니다. 실제 제작 스튜디오와 다를 수 있습니다. 확인되지 않은 제작사를 작가 이름으로 추정하지 않습니다.
- 제작사 순위는 작품 수 또는 다운로드 합계가 많은 순입니다. 같은 통합 작품을 한 번만 세며 시리즈 대표 연재판의 다운로드를 한 번만 더합니다. 미확인 다운로드는 합계에서 제외하고 확인 작품 수를 함께 표시합니다. 축약된 만·억 표시가 포함되면 합계도 근삿값입니다.
- 확보한 작품의 합계이며 회사 전체 실적이 아닙니다. 완결 보관 작품은 마지막 관측값이 포함됩니다. 제작사 미확인은 순위 밖의 별도 그룹입니다.

## 로딩과 자료 동기화

검색과 상세 화면은 저장된 자료로 즉시 구성합니다. 화면을 열 때 네이버에 요청하거나 전체 엑셀을 자동 생성하지 않습니다. 작품 목록·통합 결과는 파일 변경 때만 다시 계산하고, 공개 GitHub 자료 동기화는 백그라운드에서 진행합니다. Excel과 노션 파일은 준비 버튼을 누를 때 생성합니다.

과거 관측은 `history_index.json.gz`에 작품·플랫폼별로 압축·중복 제거해 저장합니다. `history_index.py`가 새 기록만 추가하며 대시보드는 수백 개의 원자료 이력을 다시 읽지 않습니다. 원자료는 계속 보존합니다. 매주 게시하는 메타데이터에 기록 파일의 해시를 넣고 동기화 시 검증합니다.

2026-10-30 같은 로컬 자료로 비교한 기록 조회 처리 시간은 약 22.17초에서 0.035초로 감소했습니다. 기존 관심·다운로드·댓글의 관측 시각과 값이 일치하는 것을 검증했습니다. 이는 네트워크·표지 이미지 로딩을 포함한 전체 화면 시간이 아닌 내부 처리 측정입니다.

## 갱신 정책

**매주 월요일 09:17 한국시간**에 GitHub Actions가 연재·휴재 작품을 갱신합니다. 예약 작업은 GitHub 사정으로 지연될 수 있습니다.

**완결 작품은 더 이상 갱신하지 않습니다.** 기존 완결 목록·상세 지표·시리즈 연결·관측 시각을 보관합니다. 완결 목록 endpoint도 다시 순회하지 않습니다. 연재 중 작품이 공식 응답에서 완결로 확인되면 마지막 관측을 남기고 이후 제외합니다. 완결 시리즈 판본과 완결 웹툰에 연결된 시리즈 자료도 갱신에서 제외합니다. 검색·상세 열기에서도 새로 수집하지 않습니다.

처음 자료가 없을 때만 전체 정식 공개 목록(요일별·매일+·완결)의 모든 페이지를 검증해 수집합니다. 이후에는 요일별·매일+ 목록의 신규 작품을 추가하고 기존 완결 자료를 유지합니다. 현재 목록에서 보이지 않는다는 이유만으로 삭제하거나 완결로 추정하지 않습니다. 누락된 출판사는 `publisher_enrichment.py`가 별도 보완합니다. 완결 작품도 출판사만 확인하며 기존 제목·상태·수치·수치 관측시각을 바꾸지 않습니다. 출판사 확인 시각과 출처는 `publisher_details`에 독립 저장하고, 확인된 작품은 다시 요청하지 않습니다. 매주 누락 자료를 우선 보완하며 100건마다 공개 게시합니다. 공식 시리즈 연결 미제공·원문 미표시·접근 불가를 확인 대기와 구분합니다.

주간 갱신은 하나의 `--refresh-since` 시작 시각을 모든 단계에 전달합니다. 이번 실행에서 이미 확인한 값만 재사용하며, 이전 주의 자료를 새 자료로 처리하지 않습니다. `verify_refresh.py`는 완결 보관을 제외한 작품별 관측·확인 시각을 검사하고 접근 불가를 새 수치와 별도로 집계합니다. 원래 관측 시각은 바꾸지 않습니다.

## 실행

```bash
pip install -r requirements.txt
python -m unittest discover -p 'test*.py' -v
python radar.py
python publisher_enrichment.py
python metadata.py
python series_links.py --all --limit 50
python history_index.py
python radar.py --offline
python notion_export.py
streamlit run app.py
```

주간 workflow는 같은 시작 시각을 사용해 수집·중간 게시·감사·내보내기를 실행합니다. 수동 명령의 기본 캐시는 144시간입니다. 강제 갱신은 타임존이 포함된 실행 시작 시각을 `--refresh-since`에 전달합니다. `--webtoon-limit`, `--series-limit`은 요청 예산이며 0은 해당 플랫폼을 건너뜁니다. 중간 결과는 매 20건 로컬 저장, 주간 웹툰 200건/시리즈 연결 50건마다 공개 게시합니다.

`WEBTOON_RADAR_OFFLINE=1`은 대시보드의 공개 GitHub 동기화와 수동 보완 조회를 끕니다. 코드 게시 시 수집을 재실행하지 않고 테스트만 수행합니다.

## 결과물과 노션 공유

### 작품 상세: 작가의 작품·회차·소개·추정수익

작가별 **작품 보기**는 글·그림·원작 참여 작가를 이름 단위로 비교하고, 해당 작가의 연재·휴재 작품과 완결 보관함을 구분합니다. 작품 소개는 공식 작품 페이지의 펼친 설명 원문입니다. 회차는 시리즈의 `총 N화/권`을 우선하고, 시리즈 연결이 없는 작품은 웹툰 공개 회차 목록의 개수와 최근 등록 제목을 표시합니다. 프롤로그·후기 등도 포함될 수 있어 마지막 회차의 내부 번호를 본편 회차로 추측하지 않습니다.

**추정수익 = 대표 시리즈 판본 다운로드 수 × 320원 × 0.9 = 다운로드 수 × 288원.** 사용자 지정 산식에 따른 추정액이며 실제 매출·작가 정산액은 아닙니다. 무료 이용·할인·계약 조건은 반영하지 않습니다. 원문이 만·억 단위 축약값이면 금액에도 `약`을 표시합니다. 다운로드가 원문에 없으면 다른 숫자나 0으로 대체하지 않고 `시리즈 원문 미표시`로 구분합니다.

`python profile_collection.py`는 새 소개·회차 필드를 처음 채웁니다. `--refresh`는 연재·휴재의 정보를 주간 갱신하고, 확보된 완결 소개·회차는 보존합니다. 기존 지표와 관측일을 변경하지 않으며, 재확인으로 처음 얻은 다운로드는 별도 관측 시각과 함께 빈 값만 보완합니다. 작품을 클릭할 때 원문 전체를 다시 수집하지 않습니다.

- 웹 대시보드: 표지 검색, 작품 상세·추이, 제작사별 정렬과 작품 목록
- Excel: 전체 목록, 통합 작품·제작사 순위·판본별 원자료와 출처
- SQLite·JSON: 관측별 작품 메타데이터와 실제 이력
- 요약 PDF: 범위와 수집 현황
- **`outputs/webtoon_radar_notion.zip`**: 소개 Markdown, `작품.csv`, `제작사별_순위.csv`

대시보드 아래 **노션으로 가져오기·공유 → 노션 공유 파일 준비**에서 최신 ZIP을 받을 수 있습니다. ZIP을 풀어 Markdown은 페이지로, 각 CSV는 노션 데이터베이스로 가져온 뒤 공유 링크를 만들 수 있습니다. [노션 공식 가져오기 안내](https://www.notion.com/help/import-data-into-notion)

노션 사본은 내보낸 시점의 자료이며 자동 갱신되지 않습니다. 다시 내보내 최신 자료를 가져오세요. GitHub Actions 산출물은 실행 화면 Artifacts에 90일 보관됩니다.

## 출처와 지표

[네이버웹툰 공개 목록](https://comic.naver.com/webtoon)·작품 페이지와 [네이버시리즈 만화](https://series.naver.com/comic/home.series)의 허용된 공개 경로를 이용합니다. 네이버 계약형 공식 API라고 주장하지 않습니다. 수집 전 [웹툰 robots](https://comic.naver.com/robots.txt)와 [시리즈 robots](https://series.naver.com/robots.txt)를 다시 검사하고 요청 간격을 지킵니다. 회차 본문·이미지 파일·댓글 내용·개인정보는 수집하지 않습니다. 자동 수집은 계정 쿠키나 인증 우회를 사용하지 않습니다. 정책상 제한이나 속도 제한은 중단하고, 개별 접근 불가·응답 지연은 이전 값을 보존하고 확인 상태를 기록합니다.

시리즈의 전체 분류·검색 경로는 자동 접근 제한으로 사용하지 않습니다. 만화 홈·일간 TOP100·이전 발견 작품, 웹툰 `contentsNo`와 시리즈 `originalProductId`의 공통번호로 확인한 정식 만화 작품 페이지를 사용합니다. 허용된 canonical 만화 주소로의 1회 이동만 따릅니다. **시리즈 전체 카탈로그를 확보했다는 뜻은 아닙니다.**

관심은 네이버웹툰 공개 집계 `favoriteCount`, 다운로드·댓글은 시리즈 표시값입니다. `9,985만`, `1.4만` 등은 환산값과 원문·근삿값 여부를 함께 보관합니다. 공개 목록 조회수는 양수로 제공된 경우만 기록하고 집계 범위를 추정하지 않습니다. 관심·조회수·다운로드·매출은 서로 다릅니다. 없는 값은 0으로 바꾸지 않습니다.

같은 작품은 공식 공통번호와 제목이 맞거나 정규화한 제목과 작가가 모두 또는 2명 이상 일치할 때 연결합니다. 동명 후보가 여러 개면 별도 표시합니다. 원자료와 모든 판본의 식별자·출처를 보존하며 지표는 대표 판본별로 구분합니다. 그래프는 실제 `observed_at`만 사용하고 중복을 제거합니다. 관측 한 번으로 추이나 증가율을 만들지 않습니다. 작품 표지는 공식 URL을 연결하며 권리는 각 권리자에게 있습니다.
