# Webtoon Radar

네이버웹툰 **공개 정식 작품 카탈로그 전체**를 매주 조사하는 Python · Streamlit · SQLite 프로젝트입니다. 요일별 연재작, 매일+, 완결 목록을 모두 순회하고 작품 ID로 중복을 제거합니다. 특정 인기작 표본이나 첨부 조사 PDF의 작품 목록으로 대상을 제한하지 않습니다.

## 결과물과 실행

```sh
pip install -r requirements.txt
python -m unittest discover -p 'test*.py' -v
python radar.py
python metadata.py
python series_links.py --all --limit 50
python radar.py --offline
streamlit run app.py
```

저장된 관측만 분석할 때는 `python radar.py --offline`을 실행합니다. 대시보드는 저장 관측을 읽고 공개 GitHub 저장소의 새 관측을 5분 간격으로 동기화합니다. 작품명을 검색하거나 표지 카드를 누르면 미확인 시리즈 공통번호 연결을 확인하고 재사용합니다. 전체 연결 조사는 검색 화면을 열어 두지 않아도 GitHub Actions에서 진행합니다. 검색은 띄어쓰기 차이를 허용합니다. `WEBTOON_RADAR_OFFLINE=1`이면 이 네트워크 동작을 모두 끕니다.

- 웹 대시보드: [공개 대시보드 열기](https://webtoon-survey-muhdfbebtwejruqvugroi6.streamlit.app/) · 작품명·작가·태그 검색, 장르, 관심·다운로드·댓글 태그 조합(모두/하나 이상), 최소값 필터, 지표 정렬, 상태·목록 필터, Excel 다운로드
- Excel: 전체 작품, 목록별 인기순 위치, 범위 검증 및 출처. 별도 `webtoon_radar_search.xlsx`에 장르·공개 지표·원문 표시값·태그·작품별 관측 시각을 보존합니다.
- 요약 PDF: 작품 수·상태·수집 범위와 제한사항
- SQLite: 관측 시점별 작품 및 목록 소속, JSON: 재현 가능한 원자료 메타데이터
- 주간 비교: 이전 관측 대비 목록 진입·이탈, 같은 목록 내 위치 변화. 첫 실행에서는 추세를 만들지 않습니다.

## 수집 범위와 자료 원칙

출처는 [네이버웹툰 공개 목록](https://comic.naver.com/webtoon)과 작품 페이지입니다. 공개 웹사이트가 제공하는 JSON 목록·작품 정보를 이용하며 공식 계약형 API라고 주장하지 않습니다. 작품 ID, 제목, 작가, 공개 별점, 연재 상태, 목록 내부 위치, 공개 관심 수, 장르·공식 태그를 보관합니다. 정식 공개 목록 밖의 베스트도전·도전, 비공개·판매 종료·앱 전용 작품까지 포함한다는 의미는 아닙니다.

수집 전 [robots.txt](https://comic.naver.com/robots.txt)를 다시 확인하고 허용된 목록·작품 정보 경로만 1.2초 간격으로 요청합니다. 본문·이미지 파일·댓글 내용·개인정보를 수집하지 않으며 로그인·쿠키·보호장치 우회를 사용하지 않습니다. 차단·속도 제한·응답 구조 변경은 재시도하지 않고 해당 수집을 중단하며 기존 관측을 유지합니다. 로그인·연령 확인 등 다른 경로로 이동하는 작품은 이동을 진행하지 않고 제외 기록을 남깁니다. robots 허용은 별도 이용허락이나 무제한 재사용 허가를 뜻하지 않습니다. [이용약관](https://member.webtoon.naver.com/policy/terms)을 따르는 비상업 과제용 메타데이터 조사이며 정책 변경 시 수집을 중단하고 재검토해야 합니다.

완결 목록은 응답의 총 작품 수와 모든 페이지 수를 대조합니다. 요일별·매일+는 응답 배열 전체를 읽습니다. 수집 중 목록 변동이 발견되면 결과를 게시하지 않습니다. 여러 요청의 결과이므로 수집 시작·종료 시각 사이의 관측입니다.

공개 별점은 이용자 평가이며 조회수·매출·이용자 수가 아닙니다. 인기순 위치는 해당 목록 내부 정렬 순서입니다. 요일 간 위치를 합산한 통합 순위나 공개되지 않은 지표를 생성하지 않습니다. 목록 진입·이탈을 곧바로 신작·서비스 종료로 해석하지 않습니다.

## 네이버시리즈

[시리즈 robots.txt](https://series.naver.com/robots.txt)는 만화 전체 분류와 검색 경로의 자동 접근을 제한합니다. 허용된 [만화 홈](https://series.naver.com/comic/home.series)·[일간 TOP100](https://series.naver.com/comic/top100List.series), 이전 발견 작품, 네이버웹툰 공개 `contentsNo`에서 시리즈 `originalProductId`로 확인한 작품의 상세 페이지를 읽습니다. 공통번호 조회 시 같은 호스트의 정식 만화 `productNo` 주소로 향하는 1회 이동만 허용하며, 로그인·연령확인·소설·다른 호스트·다중 이동은 따르지 않습니다. 공식 만화 주소까지 확인한 뒤 상세 페이지가 로그인으로 이동하는 경우 링크는 유지하고 지표를 공개 접근 제한으로 표시합니다. 공개 상세를 읽을 수 있는 경우 제목도 검증하며 드라마원작·영화원작 같은 명시적 홍보 표기만 정규화합니다. 주간 실행마다 미확인·갱신 대상인 전체 웹툰 목록을 순회하고 50건마다 공개 저장소에 중간 결과를 게시합니다. `Complete Series Links` 수동 실행으로 연결 조사만 재개할 수도 있습니다. **시리즈 전체 카탈로그가 아닙니다.** 장르 링크의 표시명은 읽지만 제한된 분류 링크를 따라가지 않습니다.

## 관심 수와 태그 검색

- **관심 수는 네이버웹툰 작품 페이지**의 공개 집계 `favoriteCount`입니다. 개인의 관심 등록 상태 `favorite`는 저장하지 않습니다.
- 시리즈 다운로드·댓글 수는 공개 작품 페이지의 표시값입니다. `9,985만`, `2억 8,683만`, `1.4만`은 숫자로 환산하되 원문과 근삿값 표시를 함께 보관합니다. 댓글 본문은 읽지 않습니다.
- 장르는 공개 표기 그대로 사용합니다. 웹툰의 공식 태그도 보존하며 제목으로 장르를 추정하지 않습니다.
- `관심:10만 이상`, `다운로드:100만 이상`, `댓글:1만 이상` 등의 누적 기준 태그를 만듭니다. 태그의 모두/하나 이상 포함 조건, 장르, 최소값, 검색어를 함께 적용할 수 있습니다. 축약 표시값의 경계는 실제 정확한 값과 다를 수 있습니다.
- 같은 작품은 한 행에 표시하고 **연재처**에 네이버웹툰·네이버시리즈를 함께 적습니다. 공개 공통 작품번호와 제목이 확인되거나, 제목을 정규화한 뒤 작가가 모두 일치하거나 2명 이상 일치할 때 연결합니다. 공식 번호 연결은 싸움독학처럼 작가·제작사 표기가 다른 사례에도 적용됩니다. 한글 필명의 한자 병기와 독점·단행본 같은 판본 표기만 정규화하며, 시즌·작품명 차이와 동명 후보가 여러 개인 경우는 유지합니다. 원자료 식별자는 `(플랫폼, 작품 ID)`이고 통합 작품은 각 출처를 보존합니다. 관심은 웹툰, 다운로드·댓글은 시리즈 대표 연재판에서 가져오며 플랫폼·판본 사이 수치를 합산하지 않습니다. Excel에는 통합 결과와 모든 판본의 원자료 시트가 함께 담깁니다. 미제공·수집 중·공개 접근 제한·연재처 연결 미확인은 구별하며 0으로 바꾸지 않습니다. 연결 미확인은 해당 플랫폼에 미연재라는 뜻이 아닙니다.
- 목록과 상세정보는 관측 시각이 다릅니다. 대시보드는 전체 웹툰 목록을 항상 유지하고 상세 확인 수·작품별 관측 시각을 표시합니다. 과거 목록 비교와 최신 상세 지표는 구분합니다.

`python metadata.py`는 **모든 웹툰 목록 작품**을 대상으로 상세정보를 확인합니다. 4천여 작품은 요청 간격 때문에 첫 실행에 약 85분 이상 걸릴 수 있습니다. 이후 144시간 이내 관측은 재사용합니다. 20건마다 로컬 체크포인트를 저장해 중단 후 이어서 진행할 수 있습니다. 자동 실행에서는 200건마다 공개 저장소에도 중간 결과를 게시합니다. `--webtoon-limit 100 --series-limit 100`으로 한 번의 요청 수를 제한할 수 있고 `0`은 해당 플랫폼을 건너뜁니다. 제한 옵션은 기본 전수 대상 목록을 축소하지 않습니다.

## 주간 자동 실행

GitHub Actions `Weekly Webtoon Radar`: 매주 월요일 **09:17 한국시간** 및 수동 실행. 테스트 → 전체 공개 목록 → 관심·장르·시리즈 지표 → SQLite/Excel/PDF → 관측 이력 저장 순서입니다. 코드 변경은 수집과 별개의 검증 작업만 실행하므로 진행 중인 전체 수집 때문에 배포 검증이 대기하지 않습니다. 예약·수동 실행은 전체 대상을 갱신하며 웹툰 상세정보 200건마다 중간 결과를 게시합니다. 대시보드는 게시 결과를 자동 반영합니다. 실행 상한은 360분이며 중단 후 체크포인트에서 이어서 실행할 수 있습니다. `catalog_latest.json`, `metadata_latest.json`, `history/`, `metadata_history/`를 봇이 갱신합니다. 상세 수집 중 일부가 실패해도 성공한 관측을 보존하고 실패 상태를 표시합니다. 산출물은 Actions 실행 화면의 Artifacts에서 내려받습니다(90일 보존). 저장된 관측 이력으로 다음 실행의 SQLite를 재구축합니다. GitHub 예약 작업은 지연되거나 비활성 저장소에서 중단될 수 있습니다.

## 표지 탐색과 작품 상세

검색을 메인으로 구성하고 공식 표지 URL을 연결한 카드에서 작품 상세로 이동합니다. 연재·휴재와 완결 보관함은 서로 섞이지 않습니다. 작품명·작가·요일·장르·연재처·숫자 조건 및 신작 필터와 24개 단위 페이지 이동을 제공합니다.

**신작**은 네이버웹툰 공개 목록의 `new == true`만 사용합니다. 공식 화면의 신작 배지와 대조했으며, 새 회차의 `up` 또는 수집기의 최초 발견 여부는 사용하지 않습니다. 관측 시각과 신작 근거를 Excel에도 보존합니다.

상세 화면은 관심 수, 일부 작품의 공개 목록 조회수, 시리즈 다운로드·댓글을 구분합니다. `viewCount`가 대부분 0으로 제공되어 제공 여부가 불분명하므로 양수인 값만 관측합니다. 이 조회 지표의 집계 범위는 명시되지 않았으며 누적 조회수나 고유 독자 수로 단정하지 않습니다.

그래프는 `metadata_history/`, `history/`와 현재 관측을 작품·플랫폼 ID로 대조합니다. 체크포인트 저장 시각이 아닌 각 데이터의 실제 `observed_at`을 사용하고 중복 관측을 제거합니다. 한 점만 있으면 증가율·추이를 만들지 않습니다. 서로 다른 시리즈 판본의 수치를 합치지 않습니다. 상세 화면에서 지표별 원문과 관측 CSV를 내려받을 수 있습니다.
